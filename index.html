Languages and compilers

Mettle

C · language, compiler and toolchain

A compiled, statically typed systems language where the toolchain is part of the contract. It generates native x86-64, ARM64 and GPU code with its own optimizer, linker, runtime and debugger. No LLVM, no VM, no GC. 

@simd! fn checksum(data: uint8*, n: int64) -> int64 {
  var sum: int64 = 0;
  for i: int64 in 0..n {
    sum = sum + (int64)data[i];
  }
  return sum;
}

@simd! is a demand: the loop vectorizes or the build stops. Then ask what it did:

$ mettle --build --release --explain checksum.mettle
  checksum (loop @ line 6): vectorized -> vpsadbw, 32-wide byte sum (AVX2)
Details
  • Finds use after free, double free, leaks and dangling returns while it compiles, with no lifetimes or ownership marks to write.
  • --safe checks every memory access, then proves away the checks it can.
  • --explain reports what became of every loop and call, and names the compiler's own gaps.

C99Mettle

Haskell · C compiler

A C99 compiler for Windows x86-64, written in Haskell on Mettle's backend, libmtlc. The programs it builds import kernel32.dll and nothing else: no gcc, no MSVC, no C runtime. 

build.bat
bin\c99mtlc.exe tests\fib.c -o bin\fib.exe
Details
  • Preprocessor, lexer, parser, renamer and type checker in Haskell, one module per stage; each stage rebuilds the tree rather than mutating it.
  • libmtlc takes the IR and does the rest: optimizing, emitting objects and linking the PE file.
  • Building the compiler needs only GHC and its boot libraries.

BAIE

Graphics, engines and tools

Lulkan

C++20 · Vulkan 1.3

A layer over Vulkan 1.3 that handles device setup, descriptors, barriers, synchronisation and swapchain rebuilds, while keeping Vulkan's explicit frame loop. 

lk::Frame frame = device.beginFrame();
lk::Commands& cmd = frame.commands();
cmd.beginRendering({.color = {{.texture = &frame.backbuffer()}}});
cmd.setPipeline(pipe);
cmd.bind("uTexture", tex);        // by name, via SPIR-V reflection
cmd.draw(3);
cmd.endRendering();
device.endFrame(frame);
Details
  • Descriptor layouts come from the shaders' own SPIR-V, read by a small built-in parser.
  • Barriers are tracked, not scheduled: every resource knows its last stage, access and layout.
  • Destruction waits until the GPU is done with a resource.
  • The public header includes no Vulkan headers, and no Vulkan SDK is needed to build.

Bridger

C++ · modding framework for Death Stranding

It reads the Decima engine's own type information, so mods refer to classes, fields and functions by name instead of by address: 9,867 types and 1,943 exported functions. Save a Lua file and the running game picks it up within two seconds. 

hook("EntitySymbols::Entity_ExportedHeal", function(original, entity, amount)
    return original(entity, amount * 2)
end)
Details
  • Mods read and write live objects by field name, call exports by name and hook any function or message handler.
  • Everything a mod changed reverts when it unloads, reloads or faults.
  • Mods can build engine objects with the engine's own constructors and hand them to the systems that use them, and draw on the frame with their own HLSL.
